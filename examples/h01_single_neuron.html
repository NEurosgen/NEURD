NEURD: processing a raw H01 neuron

This notebook demonstrates the supported API of a slim NEURD fork: load a raw neuron mesh, decompose it, compute spine candidates and export the result. The original algorithms and framework are credited to the upstream NEURD authors. This fork focuses on local geometry processing of single-neuron reconstructions.

The example processes the supplied raw H01 reconstruction through the public API and records processing time, resident memory and the environment used. The figure pairs its skeleton overview with a separate, manually reviewed H01 spine example whose compact meshes are included with the notebook. Saved outputs can be read without the dataset or an installed scientific environment; an HTML companion is provided for viewing in a browser.

1. Input and setup

The reference input is the local OFF file neuron_2530864375.off: 253,307 vertices, 507,737 triangular faces. Coordinates are interpreted in nanometres. Displayed lengths use micrometres; displayed spine volumes use cubic micrometres. No input decimation is requested.

Reference SHA256: ed914a7b70f370300b6ece631de9b1420eb5f0f876f01fb97f775ef63e203c3e.

The mesh is not distributed with this example. The official H01 data page describes access to reconstructions. The release layer and conversion procedure for this particular local OFF were not recovered, so that page is a data source, not a recipe for downloading a byte-identical reference file. The checksum identifies the actual input used below.

To rerun:

  1. Use the validated Linux / Python 3.12 installation with its constrained scientific packages, compiled CGAL providers, MeshLab and Xvfb.
  2. Keep this notebook, _single_neuron_example.py and the bundled data/ folder together in examples/. Select that scientific environment as your notebook kernel; notebook-tool setup is documented in the run instructions.
  3. Set NEURD_EXAMPLE_MESH before starting the kernel, or edit MESH_PATH in the next cell. For another H01 mesh, also set SEGMENT_ID to its identifier.
  4. Start a fresh kernel with PYTHONHASHSEED=0 and run all cells in order. The code sets numerical threads to one and seeds Python and NumPy with zero. Optional NEURD_EXAMPLE_CPU pins the kernel to an allowed Linux CPU; the recorded example uses CPU 2. Hardware and affinity affect timings.

NEURD_EXAMPLE_OUTPUT may name a new output directory. Otherwise a unique temporary directory is created, accessible through OUTPUT_ROOT. Existing exports are never overwritten. To inspect the full local path after execution, evaluate OUTPUT_ROOT in an extra cell.

3. Process the supplied reconstruction

The input is a raw mesh, rather than previously exported branches. The segmentation call includes soma extraction, limb and branch decomposition, skeletonization, width measurements and spine detection. It returns a Neuron object with the hierarchy soma → limb → branch → spine candidate: a limb is a connected process left after soma extraction, and branches divide it along the skeleton graph.

Intermediate files are written under _work/ in this run's output directory. Python progress messages are saved to processing.log; native-library progress may also appear in the notebook while rerunning.

6. What is optimized in this fork

This fork concentrates on local mesh decomposition and candidate detection. The changes below target expensive data structures, repeated geometry work and native/Python I/O. They describe implementation mechanisms; the recorded time and memory above are one observation of the current pipeline.

Area Implemented change Purpose
OFF loading Parse supported triangular OFF files into preallocated numeric arrays with bounded input validation; retain a compatibility fallback. Avoid building a large collection of Python objects while reading geometry.
Connected components Compute sparse vertex components and derive face components from their labels. Avoid allocating the dense vertex-to-face representation used by the upstream route.
Coordinate matching Use cKDTree searches in the patched matching routines. Avoid materializing a matrix of every pairwise coordinate distance.
Segmentation assembly Read CGAL labels/SDF once, group face indices stably and assemble each selected mesh once. Reduce repeated grouping, extraction and concatenation of geometry.
Piece adjacency Index the pieces incident to each shared vertex. Discover neighboring pieces without repeatedly intersecting every pair of vertex sets.
Temporary geometry Reclaim unused objects at stage boundaries and clear derived mesh caches. Release intermediate allocations and, where supported, return free allocator pages to the OS.
Native output Keep CGAL CSV output buffered instead of flushing the stream for every record. Reduce repeated per-record stream flushes.

The supported workflow is also easier to configure: RunConfig carries the dataset, spine mode, SDF profile and refinement policy; loading, processing and export are separate public calls. Shared batch utilities provide isolated workers and resume checks. The constrained installation profile records the dependency versions used for the reference result.

The fast / 12-ray SDF setting is an explicit processing choice. It changes the sampling budget, and should be selected with the required detection quality in mind. This example uses refinement off.

These engineering changes do not establish anatomical accuracy. Candidate masks, face provenance and saved geometry make the output inspectable; validation of spine detection needs annotated examples.
